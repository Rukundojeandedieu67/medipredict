## 2) Provenance evidence

### `datasets/medipredict_data/raw/rwanda_healthsites.csv`
- Claimed source: HDX Rwanda Healthsites CSV, with URL embedded in `datasets/download_and_build_medipredict_data.py`.
- Evidence: the script contains `https://data.humdata.org/dataset/.../download/rwanda.csv` and the file has OpenStreetMap-style fields (`osm_id`, `X`, `Y`, `amenity`, `source`, `changeset_id`, `changeset_timestamp`, `uuid`).
- Proof: the file contains actual OSM/Healthsites-style coordinates, one row per facility, and a full source field list; no synthetic code path is present in the script for this raw file.
- Verdict: REAL. Confidence: high.

### `datasets/medipredict_data/processed/nisr_census_2022_districts.csv`
- Claimed source: NISR 2022 census / RDHS / EICV indicators, in comments in `datasets/download_and_build_medipredict_data.py`.
- Evidence: the script literally hardcodes a 30-district list and writes it to `processed/nisr_census_2022_districts.csv`.
- Proof: the file is generated by the script; the script shows a `nisr_district_db = [...]` list, not an external download. There is no official URL, publication DOI, or source table in the repo for this file.
- Verdict: UNVERIFIED. Confidence: high. The file is not a verified official export; it is a repository seed table.

### `datasets/medipredict_data/processed/district_climate_rainfall.csv`
- Claimed source: Open-Meteo forecast API.
- Evidence: the script calls `https://api.open-meteo.com/v1/forecast?latitude=...&longitude=...&daily=precipitation_sum,temperature_2m_max...` and falls back to `weekly_avg_rainfall_mm = 4.5` on exception.
- Proof: only 5 districts are present instead of all 30; the script explicitly writes a fallback value for failed API requests. The file is therefore a derived, incomplete climate table, not a canonical weather source.
- Verdict: REAL-DERIVED. Confidence: medium.

### `datasets/medipredict_data/processed/medipredict_master_rwanda_dataset.csv`
- Claimed source: “NISR Census 2022 + RDHS + e-LMIS Fused Stream” in `data_source_verification`.
- Evidence: the generator file contains `np.random.seed(2026)` and uses `np.random.randint`, `np.random.choice`, and formula-driven risk labels. It explicitly computes `current_stock_units`, `avg_daily_consumption_units`, `pending_depot_orders_units`, and `predicted_risk_level` from synthetic formulas.
- Proof: the file has 120 rows (30 districts × 4 medicine types) and all operational fields are generated: `current_stock_units` values range 812 to 24,314, `pending_depot_orders_units` are only `0`, `500`, `1000`, or `2000`, and `risk_values` are exactly `CRITICAL`, `MODERATE`, `STABLE`.
- Verdict: SYNTHETIC. Confidence: high.

### `datasets/medipredict_data/processed/medipredict_facility_timeseries_2026.csv`
- Claimed source: derived facility-level time series for January-October 2026.
- Evidence: `datasets/build_facility_timeseries.py` initializes `np.random.seed(42)` and creates synthetic inventory trajectories for `facility_name, district, province, medicine_code` using random stock and consumption changes with rainy-season multipliers.
- Proof: the output has exactly 6000 rows = 150 facilities × 4 medicines × 10 months; the code loops `for med in essential_medicines` and `for month in months_2026`; `rainy_season_active` is a deterministic 0/1 flag triggered by month, and `stock_end_month` is generated with random choice from `[0, 1000, 2000]`.
- Verdict: SYNTHETIC. Confidence: high.

### Files with no provenance or no proof of source
- `datasets/medipredict_data/processed/district_climate_rainfall.csv`: no provenance README or source manifest; fallback logic means file is incomplete and mixed.
- `datasets/medipredict_data/processed/nisr_census_2022_districts.csv`: no official publication citation or URL. As the repo itself says, this is an unverified seed table.

## 3) Synthetic fingerprints and violations

### Files with `is_synthetic` or generator-origin evidence
- `datasets/medipredict_data/processed/medipredict_master_rwanda_dataset.csv`: no `is_synthetic` column, but the generator script is explicit about simulation.
- `datasets/medipredict_data/processed/medipredict_facility_timeseries_2026.csv`: no `is_synthetic` column, but the generator script is explicit about random generation and deterministic `np.random.seed`.
- `datasets/medipredict_data/processed/district_climate_rainfall.csv`: no `is_synthetic` column; file contains a fallback value `4.5` that is used when API requests fail.

### Numbers that indicate synthetic or derived data
- `medipredict_facility_timeseries_2026.csv`
  - 6000 rows exactly = 150 facilities × 4 medicines × 10 months.
  - 150 unique facilities, 30 districts, 4 medicine codes; all 10 reporting months are present with exactly 600 rows each.
  - 0 missing values in a table intended to be a messy facility log.
  - `stock_floor_50_rows`: 1530 rows equal exactly 50, which is a strong sign of a clipped synthetic floor.
  - `lead_time_days_remaining` maximum = 314.4, which is implausibly large for a stock-days metric in a facility log; 1020 rows exceed 90 days.
  - `rainy_season_active` count = 2400, exactly matching the expected seasonal months; this is a patterned artifact.
  - `lead_formula_mismatches`: 0. The script computes them from stock and consumption, so the values are internally consistent but synthetic.

- `medipredict_master_rwanda_dataset.csv`
  - 120 rows = 30 districts × 4 medicines.
  - `pending_depot_orders_units` values are only `0`, `500`, `1000`, or `2000` with `0` in 42 rows, which is a very small discrete domain.
  - `estimated_lead_time_days` max = 45.2 and `current_stock_units` range = 812 to 24,314.
  - `data_source_verification` is exactly one repeated string for all 120 rows: `NISR Census 2022 + RDHS + e-LMIS Fused Stream`. This is not evidence of a real source; it is a label set in code.
  - No `is_synthetic` column exists despite the generator’s explicit simulation logic.

- `district_climate_rainfall.csv`
  - Only 5 rows, covering 5 districts, while the repo claims Rwanda has 30 districts.
  - `district_climate_rainfall.csv` has 5 of 30 districts; the missing districts are: Bugesera, Burera, Gakenke, Gatsibo, Gicumbi, Kamonyi, Karongi, Kayonza, Kirehe, Muhanga, Musanze, Ngoma, Ngororero, Nyabihu, Nyagatare, Nyamagabe, Nyamasheke, Nyanza, Nyaruguru, Rubavu, Ruhango, Rulindo, Rusizi, Rutsiro, Rwamagana.
  - 1 row equals `4.5`, which is the script’s fallback value when API requests fail.

### Rwanda sanity checks
- Census reference check (`datasets/medipredict_data/processed/nisr_census_2022_districts.csv`):
  - 30 unique districts, 30 rows.
  - 5 province names: `Southern`, `Western`, `Eastern`, `Northern`, and `Kigali City`.
  - Population sum = 13,215,818; under-5 total = 1,675,739; under-5 share of total = 12.68%.
  - This matches the 2022 Rwanda census order-of-magnitude expectation.
  - District names are spelled consistently and there are no duplicate district rows.
  - No invalid percentage rows (all `poverty_rate_pct`, `mutuelle_pct`, `malaria_prev_pct`, `delivery_facility_pct` fall inside 0–100).

- Health facility raw source (`datasets/medipredict_data/raw/rwanda_healthsites.csv`):
  - 1359 rows.
  - 105 rows have missing `X` or `Y`, which is normal for a source CSV with partial metadata.
  - All non-null coordinates are within the Rwanda bounding box (-2.85 to -1.05 latitude, 28.85 to 30.90 longitude): 1254 of 1359 rows are within bounds and 0 non-null rows are outside the box.
  - `X` / `Y` overall follows the expected Rwanda coordinate ranges; no impossible coordinates were found.

- Facility tier check (using the repo-generated `ml_engine/datasets/processed/facilities.csv` derived from the raw points):
  - 1254 rows after invalid coordinate filtering.
  - 30 districts; 5 provinces; all facility coordinates fall inside Rwanda’s bounding box.
  - Derived facility types are `Hospital` (657), `Pharmacy` (481), `Health Center` (103), `Other` (13).
  - No row violates the Rwanda bounding box, and no district is missing.
  - The repo does not include a `referral hospital` category; the facility-tier categories are not exactly the three-tier scheme the task expects, but they do not contradict Rwanda geography.

## 4) What must be verified manually

These cannot be proven from the repo alone:

1. Download URL and publisher for the raw Healthsites CSV: the repository references the HDX URL, but the repo does not retain the final HTML landing page, access date, or dataset license metadata beyond the script text.
2. Official publication for the district indicators: the repo contains a hardcoded seed table and comments naming NISR / RDHS / EICV, but it does not include the exact publication URL, dataset title, date accessed, or publisher for the district-level counts used in `nisr_census_2022_districts.csv`.
3. Official climate data source and access date: `district_climate_rainfall.csv` came from the Open-Meteo API, but the file itself has no API response metadata, access timestamp, or coverage notes for all 30 districts.
4. Source of the health facility reference layer used for district assignment: `build_reference_data.py` downloads a GeoBoundaries ADM2 file dynamically, but no archived download URL or publisher record is stored in the repo to prove the exact boundary file version beyond the runtime API response.

## 5) Recommended fixes

1. Add a row-level `is_synthetic` flag and explicit `data_source` column to:
   - `medipredict_master_rwanda_dataset.csv`
   - `medipredict_facility_timeseries_2026.csv`
   - `district_climate_rainfall.csv`
2. Move or relabel generated operational files to a clearly synthetic folder, or add README notes stating these are demo/training data and not operational data.
3. Replace the hardcoded `nisr_district_db` seed with a citation-backed official dataset (with publisher, URL, access date, and citation) or clearly mark the table as `UNVERIFIED` in the directory README.
4. Add a per-dataset README in `datasets/medipredict_data/` explaining source, retrieval date, publisher, and license for each file.
5. Add a facility-tier validation step to ensure the canonical categories are `referral hospital`, `hospital`, and `health center` or document why `Pharmacy` and `Other` are intentionally retained.
6. Populate `district_climate_rainfall.csv` for all 30 districts and record whether a row was produced by a live API fetch or a fallback value.
